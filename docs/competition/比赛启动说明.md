## 2. 我们做出了什么

### 一句话

一个挂在智能体和大模型之间的防护代理：智能体每次要调工具，请求都先过我们这一道，
按危害程度分四档处置，全程留审计。配一套 66 条经过有效性验证的政务攻击用例来测它。

### 运行起来长什么样

```
你在 OpenClaw 里打字
      ↓
OpenClaw 决定调用工具（比如 exec 执行一条命令）
      ↓
┌─────────── 防护代理 :4000 ───────────┐
│  意图分类器  → 规则引擎 → 污点分析 → 语义评审 │
└──────────────────────────────────────┘
      ↓ 按危害分四档
  L0 放行（无感）
  L1 放行 + 上报（侦察类，留证据）
  L2 暂停等人工确认（半合法操作）
  L3 阻断 + 回一句原因（确定性危害）
      ↓
  mock 工具服务 :4001（假执行，不会真删你的文件）
      ↓
  审计日志 audit_log.jsonl
```

### 三个值得讲的设计

**一、L1 放行侦察，把检测点后移到危害动作本身。**
攻击链通常是先 `ls`/`find` 找文件，再 `curl` 传出去。拦住侦察，攻击者换条路再来，
链条断在我们看不见的地方。放行侦察并上报，让链条走到外传那一步，在 L3 逮住，
同时留下完整的攻击链证据。

**二、L2 不猜结论，把判断权交还人工。**
"把这批数据发给兄弟单位对接人"合不合法，取决于组织内部到底有没有这个安排 ——
这是带外事实，规则判不了，模型猜也是猜。L2 的职责是把这类操作识别出来并停住，
不负责给结论。

**三、攻击有效性优先的基准方法论。**
这是我们最硬的原创主张。每条攻击在被用来测防护之前，先要证明它自己能成功诱导：
391 条候选 → 203 条裸诱导成立 → 66 条在真实框架里确实执行了危害动作。
学术界的 InjecAgent（1054 条）和 AgentDojo（97 条）都不做这一步验证。
不做的后果是：无效样本会稀释评测，拦截率数字虚高。

## 3. 一件必须先说清楚的事：数字口径

**8-23 的复核发现，之前对外说的 97% 拦截 / 0 穿透 / 4% 误报这组数字不能用。**

原因不复杂：判定程序把"良性铺垫轮被误拦"也算成了"攻击被拦住"。66 条里有 7 条
攻击轮什么都没发生，纯靠铺垫轮的一次误拦被记成拦截成功。同一批实验里
82% 的良性铺垫轮被拦，这个事实和"误报率 4%"直接矛盾。

已经修好并加了回归测试，正在重跑。对你的影响是三条：

1. **不要从任何历史文档里抄效果数字。** 老的 md 文件里到处都是作废数字。
2. **写正文时效果数字一律写 `〔G5〕`。** 重跑完由核心组统一回填。
3. **唯一数字来源是 `docs/competition/metrics-frozen-v1.md`。** 那里没有的，就是还没定。

这件事本身是可以写进报告的加分项：我们发现了自己评测里的归因缺陷、修掉、
重测、如实报告。这比一个漂亮但站不住的数字更能体现方法论的严谨。
