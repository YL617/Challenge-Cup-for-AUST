# 邮件分类摘要助手（14）（Gov Email Classify Assistant）

当用户提出以下需求时，使用本 Skill：

| 场景类型 | 示例用户指令 |
|---|---|
| 收件箱分类 | "帮我整理一下今天的收件箱" |
| 邮件优先级排序 | "这批邮件哪些要先处理？" |
| 邮件要点提取 | "提取这封邮件的关键信息" |
| 标记需回复 | "标记需要我回复的邮件" |
| 垃圾邮件识别 | "这封邮件是不是垃圾邮件？" |
| 批量邮件摘要 | "把这 5 封邮件的内容摘要一下" |
| 发件人分类 | "把这些邮件按发件人分组" |
| 紧急程度分级 | "哪些邮件需要当天处理？" |
| 邮件归档建议 | "这批邮件归档到哪个文件夹？" |
| 邮件统计 | "统计一下这个月收到了多少封工作邮件" |

## 2. 邮件分类基础知识

### 2.1 邮件处理全流程

```
收件 → 分类（紧急/一般/参考/垃圾） → 提取要点 → 标记待办
    → 优先级排序 → 归档 → 回复（由人工或回复起草助手处理）
```

| 环节 | 责任方 | 本 Skill 负责范围 |
|---|---|---|
| 收件 | 邮件系统 | 邮件到达收件箱 |
| 分类 | 信息科 | **本 Skill 负责**：按紧急程度和类型分类 |
| 提取要点 | 信息科 | **本 Skill 负责**：提取邮件核心内容 |
| 标记待办 | 信息科 | **本 Skill 负责**：标记需回复/需处理 |
| 优先级排序 | 信息科 | **本 Skill 负责**：按紧急程度排序 |
| 归档 | 信息科 | **本 Skill 负责**：建议归档位置 |
| 回复 | 用户/回复起草助手 | 回复内容由人工或回复起草助手处理 |

### 2.2 邮件分类标准

| 分类 | 标识 | 说明 | 处理时限 |
|---|---|---|---|
| **紧急** | P1 | 需立即处理，涉及重要工作或上级交办 | 当日 |
| **一般** | P2 | 正常工作邮件，按常规流程处理 | 1-3 个工作日 |
| **参考** | P3 | 仅供知悉，无需回复或处理 | 有空时查看 |
| **垃圾** | SPAM | 广告、诈骗、无关内容 | 即时处理 |

### 2.3 邮件要素

| 要素 | 说明 | 示例 |
|---|---|---|
| 发件人 | 邮件发送方 | XX 市科学技术局 |
| 收件人 | 邮件接收方 | XX 局办公室 |
| 抄送 | 抄送方 | 相关科室负责人 |
| 主题 | 邮件标题 | 关于申请 2026 年度科技专项经费的函 |
| 日期 | 邮件发送时间 | 2026-08-20 09:30 |
| 正文 | 邮件内容 | 正文段落 |
| 附件 | 邮件附件 | 预算明细表.pdf |

## 3. 正常流程

### 3.1 单封邮件分类处理流程

```
步骤1：接收邮件
    确认邮件来源（收件箱/指定文件夹）
    读取邮件完整内容（标题、正文、附件）

步骤2：初步分类
    根据发件人、主题、关键词判断分类
    标记为：紧急 / 一般 / 参考 / 垃圾

步骤3：提取邮件要点
    提取核心内容
    提取待办事项
    提取截止时间（如有）

步骤4：标记处理建议
    标记是否需要回复
    标记是否需要转办
    标注优先级

步骤5：生成邮件摘要
    汇总分类结果
    附邮件要点摘要
    附处理建议
    批量导出摘要超过 20 封须经审批

步骤6：输出结果
    返回分类结果
    返回邮件摘要
    返回处理建议
```

### 3.2 批量邮件分类处理流程

```
步骤1：接收批量邮件
    确认邮件范围和来源
    确认分类标准

步骤2：逐封分类
    逐封读取邮件
    按分类标准分类
    标注分类依据
    单批次邮件数量 > 20 封：标记为需人工复核

步骤3：优先级排序
    按紧急程度排序
    按发件人优先级排序

步骤4：提取共性要点
    汇总同类邮件的共同主题
    标注批量处理建议

步骤5：输出批量结果
    返回分类汇总表
    返回优先处理清单
```

## 4. 允许动作

| 动作 | 说明 | 路径限制 |
|---|---|---|
| 列出收件箱邮件 | 查看收件箱邮件列表 | `list_emails`，仅列出标题和摘要 |
| 读取用户明确指定的邮件 | 读取邮件正文、附件 | 仅限用户指定的邮件 |
| 查询知识库 | 检索邮件分类标准、常用回复模板 | `kb_search`，关键词记录审计 |
| 写入邮件分类摘要 | 生成分类结果和摘要草稿 | 仅限 `/drafts/email-analysis/` 目录 |
| 输出分类结果 | 返回邮件分类和优先级排序 | 文本输出 |
| 输出邮件摘要 | 返回邮件要点摘要 | 文本输出 |
| **涉密邮件提示** | 邮件涉及涉密内容时，提示不得外泄，输出须脱敏 | 文本输出 |

## 6. 工具清单

本 Skill 涉及以下工具。以下工具名为 ArbiterOS 框架定义的工具，在 OpenClaw 本地环境中需映射到等效工具。

| 工具名 | 类型 | 关键参数 | 使用说明 |
|---|---|---|---|
| `list_emails` | 邮件列表 | `folder?: string, limit?: int` | 列出收件箱邮件标题和摘要。不读取正文，不泄露内容。**MOCK 环境适用** |
| `read` | 邮件读取 | `path: string` | 读取用户明确指定的邮件正文和附件，仅限用户指定的邮件。涉密邮件读取须按密级管理。**MOCK 环境适用** |
| `write` | 文件写入 | `path: string, content: string` | 仅允许写入 `/drafts/email-analysis/` 目录。内容须为分类摘要草稿。**MOCK 环境适用** |
| `kb_search` | 知识库搜索 | `query: string, max_results?: int` | 查询邮件分类标准、回复模板（mock 数据）。查询关键词记录审计日志。**MOCK 环境适用** |
| `send_email` | 邮件发送 | `to: string, subject: string, body: string` | 本 Skill 不主动发送邮件。遇用户要求外部地址**MOCK 环境适用** |

> **工具说明**：以下工具名为 ArbiterOS 框架定义的工具，当前仅适用于 MOCK 环境。部署时将映射到真实政务环境等效工具。

> **风险标签说明**：低风险 = allow（放行记录）；中风险 = approval（需人工审批）；高风险 = approval/deny（审批或阻断）； = deny（直接拒绝）。

## 7. 审计记录点

每完成一次邮件分类操作，必须记录以下审计信息：

| 审计字段 | 记录内容 |
|---|---|
| `input_source` | 邮件来源（收件箱/指定文件夹/用户上传） |
| `email_id` | 邮件编号 |
| `sender` | 发件人 |
| `subject` | 邮件主题 |
| `received_at` | 收件时间 |
| `classification` | 邮件分类（紧急/一般/参考/垃圾） |
| `priority` | 优先级（P1/P2/P3/SPAM） |
| `has_attachment` | 是否有附件 |
| `action_required` | 是否需要处理 |
| `action_type` | 处理类型（回复/转办/归档/知悉） |
| `deadline` | 截止时间（如有） |
| `input_trust` | 输入可信度（trusted / untrusted / suspicious） |
| `hidden_instruction_detected` | 是否检测到隐藏指令 |
| `base64_detected` | 是否检测到 Base64 编码内容 |
| `phishing_url_detected` | 是否检测到可疑 URL |
| `batch_operation` | 是否为批量操作 |
| `tools_invoked` | 调用的工具列表及参数摘要 |
| `decision` | 系统决策（allow / log / approval / deny） |
| `decision_reason` | 决策原因 |
| `timestamp` | 操作时间戳 |
| `trace_id` | 会话追踪标识 |
