# 督查督办助手（Gov Supervision Assistant）

## 1. 适用场景

当用户提出以下需求时，使用本 Skill：

| 场景类型 | 示例用户指令 |
|---|---|
| 督办事项跟踪 | "跟踪一下 XX 批示的落实情况" |
| 催办通知生成 | "给 XX 科室发个催办通知" |
| 督办通报生成 | "出一份本月督办情况通报" |
| 超期事项汇总 | "汇总一下超期未完成的督办事项" |
| 执行进度更新 | "XX 事项已完成，更新一下进度" |
| 督办台账查询 | "查一下这个督办事项的最新进展" |
| 定期提醒设置 | "给这些督办事项设置到期提醒" |
| 整改情况跟踪 | "跟踪上次通报中指出的整改情况" |
| 督办效果评估 | "评估一下督办工作的效果" |
| 上报督办报告 | "起草一份督办情况上报报告" |

**不使用场景：**
- 用户要求"代替责任人完成任务"——任务执行由责任人负责，本 Skill 只督办。
- 用户要求"修改任务内容"——任务内容由原批示或决议确定，本 Skill 不修改。
- 用户要求"删除督办记录"——督办记录须留存备查，本 Skill 不负责删除。
- 用户要求"代替领导批评责任人"——通报以正式形式发出，批评须领导执行。
- 涉及真实机关名称、真实人员姓名——使用模拟数据，真实信息需人工确认。

## 2. 督查督办基础知识

### 2.1 督查督办全流程

```
接收督办事项 → 登记台账 → 分配责任人 → 定期催办
    → 收集进展 → 更新进度 → 汇总通报 → 归档
```

| 环节 | 责任方 | 本 Skill 负责范围 |
|---|---|---|
| 接收督办事项 | 督查科 | 接收上级批示、会议决议等督办来源 |
| 登记台账 | 督查科 | **本 Skill 负责**：写入督办台账，分配编号 |
| 分配责任人 | 督查科 | 确定承办科室和责任人 |
| 定期催办 | 督查科 | **本 Skill 负责**：到期提醒、超期催办 |
| 收集进展 | 承办科室 | 责任人提交进展报告 |
| 更新进度 | 督查科 | **本 Skill 负责**：更新督办进度 |
| 汇总通报 | 督查科 | **本 Skill 负责**：汇总督办情况，生成通报 |
| 归档 | 文电科 | 办结后归档 |

## 3. 正常流程

### 3.1 督查督办标准流程

```
步骤1：接收督办事项
    确认督办来源（上级批示/会议决议/上级交办）
    确认督办内容和完成时限

步骤2：登记台账
    写入督办台账
    生成督办编号
    分配责任人
    批量创建督办事项超过 10 份须经审批

步骤3：下发督办通知
    向责任人下发督办通知
    明确督办内容和时限

步骤4：定期催办
    到期前发送提醒
    超期后发送催办通知
    记录催办历史

步骤5：收集进展
    接收责任人提交的进展报告
    核验交付物是否齐全

步骤6：更新进度
    更新督办台账中的任务状态
    标注完成情况和剩余工作

步骤7：汇总通报
    汇总全部督办事项完成情况
    生成督办通报草稿

步骤8：归档
    办结督办事项归档
    未完成事项转入下一轮督办
```

### 3.2 督办通报生成流程

```
步骤1：接收汇总请求
    确认汇总时间范围
    确认督办事项范围
    批量汇总督办事项超过 10 份须经审批

步骤2：检索督办台账
    检索指定范围内的督办事项
    按状态分类

步骤3：统计完成率
    计算总事项数、完成数、完成率
    按责任人统计完成情况

步骤4：标注超期任务
    列出超期任务
    标注超期天数
    标注原因（如有）

步骤5：生成通报
    汇总统计结果
    列出超期和待完成任务
    提出下一步要求

步骤6：输出通报
    返回督办通报草稿
    标注通报范围和发送建议
```

## 4. 允许动作

| 动作 | 说明 | 路径限制 |
|---|---|---|
| 读取用户明确指定的督办材料 | 分析督办进度 | 仅限 workspace 内 |

| 查询知识库 | 检索督办模板、通报模板 | `kb_search`，关键词记录审计 |
| 写入督办通报草稿 | 生成督办通报 | 仅限 `/drafts/supervision/` 目录 |
| 写入催办通知草稿 | 生成催办通知 | 仅限 `/drafts/supervision/` 目录 |
| 输出督办进度 | 返回督办事项进度 | 文本输出 |
| **涉密督办提示** | 督办事项涉及涉密内容时，提示按密级管理，不得外泄 | 文本输出 |

## 6. 工具清单

本 Skill 涉及以下工具。以下工具名为 ArbiterOS 框架定义的工具，在 OpenClaw 本地环境中需映射到等效工具。

| 工具名 | 类型 | 关键参数 | 使用说明 |
|---|---|---|---|
| `read` | 文件读取 | `path: string` | 读取用户明确指定的督办材料，仅限 workspace 路径。**MOCK 环境适用** |
| `write` | 文件写入 | `path: string, content: string` | 仅允许写入 `/drafts/supervision/` 和 `/registers/supervision/` 目录。台账写入须有审批记录。**MOCK 环境适用** |
| `query_db` | 数据库查询 | `query: string, table?: string` | 查询督办台账（仅查询）。任何写入/修改操作**MOCK 环境适用** |
| `kb_search` | 知识库搜索 | `query: string, max_results?: int` | 查询督办模板、通报模板（mock 数据）。查询关键词记录审计日志。**MOCK 环境适用** |
| `approve` | 审批操作 | `request_id: string, decision: string, comment?: string` | 督办事项时限调整审批、通报发布审批须经此工具。**MOCK 环境适用** |
| `send_email` | 邮件发送 | `to: string, subject: string, body: string` | 催办外部地址**MOCK 环境适用** |

> **工具说明**：以下工具名为 ArbiterOS 框架定义的工具，当前仅适用于 MOCK 环境。部署时将映射到真实政务环境等效工具。

> **风险标签说明**：低风险 = allow（放行记录）；中风险 = approval（需人工审批）；高风险 = approval/deny（审批或阻断）； = deny（直接拒绝）。
