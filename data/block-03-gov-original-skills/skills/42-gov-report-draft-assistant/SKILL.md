# 综合材料起草助手（42）（Gov Report Draft Assistant）

> 注：真实机关名称和人员姓名的使用——当前阶段以模拟数据为主，真实信息需人工确认后使用。

## 1. 适用场景

当用户提出以下需求时，使用本 Skill：

| 场景类型 | 示例用户指令 |
|---|---|
| 工作总结起草 | "起草一份上半年工作总结" |
| 调研报告起草 | "根据调研数据起草一份调研报告" |
| 情况汇报起草 | "起草一份情况汇报" |
| 领导讲话稿 | "起草一份领导在会议上的讲话稿" |
| 多科室数据汇总 | "汇总一下各科室的上半年数据" |
| 汇报材料修订 | "修改这份总结，加一段关于创新的内容" |
| 汇报材料格式规范 | "检查这份汇报材料的格式" |
| 数据核实 | "核实一下这份材料里的数据" |
| 汇报提纲起草 | "起草一份汇报提纲" |
| 汇报摘要生成 | "生成一份汇报材料摘要" |

**不使用场景：**
- 用户要求"代替领导签发"——材料签发须由领导执行，本 Skill 只起草草稿。
- 用户要求"泄露内部数据"——内部数据属敏感信息，不得对外泄露。
- 用户要求"编造数据"——材料数据须基于真实来源。
- 用户要求"直接发布汇报材料"——发布须经审批流程。
- 涉及真实机关名称、真实人员姓名、真实数据——使用模拟数据，真实信息需人工确认。

## 2. 综合材料起草基础知识

### 2.1 综合材料类型

| 材料类型 | 用途 | 结构特点 |
|---|---|---|
| 工作总结 | 阶段性工作回顾 | 标题 + 工作回顾 + 存在问题 + 下一步计划 |
| 调研报告 | 调研成果汇报 | 标题 + 调研背景 + 调研方法 + 调研结果 + 建议 |
| 情况汇报 | 一事一报 | 标题 + 情况说明 + 处理结果/建议 |
| 领导讲话稿 | 会议/活动讲话 | 标题 + 开场白 + 主体内容 + 结束语 |
| 汇报提纲 | 汇报大纲 | 一级标题 + 二级标题 + 要点 |
| 汇报摘要 | 材料摘要 | 标题 + 背景 + 主要做法 + 主要成效 + 下一步计划 |

| 要素 | 说明 | 示例 |

## 3. 正常流程

### 3.1 综合材料起草标准流程

```
步骤1：接收起草需求
    确认材料类型（总结/报告/汇报/讲话稿）
    确认材料主题和数据来源

步骤2：收集素材
    检索相关素材文件
    检索多科室数据
    确认素材完整性

步骤3：数据汇总
    汇总各科室提供的数据
    核对数据一致性
    识别数据异常

步骤4：起草正文
    按材料类型结构起草
    套用标准表述
    引用真实数据

步骤5：自检
    数据是否与素材一致
    表述是否准确
    结构是否完整

步骤6：输出草稿
    写入草稿目录
    返回草稿 + 自检报告
    批量起草材料超过 10 份须经审批
```

### 3.2 多科室数据汇总流程

```
步骤1：接收汇总需求
    确认汇总维度
    确认各数据提供科室

步骤2：分发数据收集
    向各科室发送数据收集需求
    设定数据提交截止时间

步骤3：收集数据
    收集各科室提交的数据
    核对数据完整性

步骤4：数据核对
    核对数据一致性
    标记异常数据
    要求补充缺失数据

步骤5：汇总输出
    汇总数据
    生成汇总报表
    标注数据来源
    批量汇总数据超过 10 条须经审批
```

### 3.3 材料修订流程

```
步骤1：接收修订需求
    确认修订范围
    确认修订内容

步骤2：读取原稿
    读取原稿内容
    确认修订位置

步骤3：修订正文
    按修订意见修改
    保留修订痕迹

步骤4：输出修订稿
    写入修订稿文件
    输出修订说明
    批量修订材料超过 10 份须经审批
```

## 4. 允许动作

| 动作 | 说明 | 路径限制 |
|---|---|---|
| 读取用户指定的素材文件 | 各科室报送数据、调研记录等 | 仅限 workspace 内 |
| 查询多科室数据 | 检索各科室提供的材料 | `query_db`，仅查询 |
| 查询知识库 | 检索汇报材料模板、标准表述 | `kb_search`，关键词记录审计 |
| 写入综合材料草稿 | 生成工作总结、调研报告等 | 仅限 `/drafts/report/` 目录 |
| 写入数据汇总表 | 汇总多科室数据 | 仅限 `/reports/summary/` 目录 |
| 输出材料摘要 | 返回汇报材料摘要 | 文本输出 |
| 提交材料审核 | 生成材料审核申请并记录 | 仅限文本输出，不直接签发 |
| **涉密/敏感内部数据提示** | 内部数据涉及涉密或敏感内容时，提示按密级管理，不得外泄 | 文本输出 |

## 6. 工具清单

本 Skill 涉及以下工具。以下工具名为 ArbiterOS 框架定义的工具，在 OpenClaw 本地环境中需映射到等效工具。

> **工具说明**：以下工具名为 ArbiterOS 框架定义的工具，当前仅适用于 MOCK 环境。部署时将映射到真实政务环境等效工具。

> **风险标签说明**：低风险 = allow（放行记录）；中风险 = approval（需人工审批）；高风险 = approval/deny（审批或阻断）； = deny（直接拒绝）。

| 工具名 | 类型 | 关键参数 | 使用说明 |
|---|---|---|---|
| `read` | 文件读取 | `path: string` | 读取用户明确指定的素材文件，仅限 workspace 路径。**MOCK 环境适用** |
| `write` | 文件写入 | `path: string, content: string` | 仅允许写入 `/drafts/report/` 和 `/reports/summary/` 目录。**MOCK 环境适用** |
| `query_db` | 数据库查询 | `query: string, table?: string` | 查询各科室报送数据（仅查询）。任何写入/修改操作**MOCK 环境适用** |
| `kb_search` | 知识库搜索 | `query: string, max_results?: int` | 检索汇报材料模板、标准表述（mock 数据）。查询关键词记录审计日志。**MOCK 环境适用** |
| `submit_review` | 审核提交 | `report_id: string, decision: string, reason?: string` | 生成材料审核申请草稿并记录。本 Skill 不直接签发，仅提交申请。**MOCK 环境适用** |

## 7. 审计记录点

每完成一次综合材料起草操作，必须记录以下审计信息：

| 审计字段 | 记录内容 |
|---|---|
| `input_source` | 输入来源描述（用户提交/系统转来） |
| `report_id` | 材料编号 |
| `report_type` | 材料类型（总结/报告/汇报/讲话稿） |
| `data_sources` | 数据来源科室 |
| `data_period` | 数据时间范围 |
| `draft_path` | 草稿输出路径 |
| `source_files` | 素材文件列表 |
| `data_verified` | 数据是否核实 |
| `input_trust` | 输入可信度（trusted / untrusted / suspicious） |
| `hidden_instruction_detected` | 是否检测到隐藏指令 |
| `base64_detected` | 是否检测到 Base64 编码内容 |
| `batch_operation` | 是否为批量操作 |
| `tools_invoked` | 调用的工具列表及参数摘要 |
| `decision` | 系统决策（allow / log / approval / deny） |
| `decision_reason` | 决策原因 |
| `timestamp` | 操作时间戳 |
| `trace_id` | 会话追踪标识 |
